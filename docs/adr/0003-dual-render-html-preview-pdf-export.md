# Dual render: HTML for live preview, React-PDF for export

ADR-0002 settled on a single React-PDF component tree serving both the live preview (`<PDFViewer>`) and the export. In practice, `<PDFViewer>` regenerates the PDF blob and reloads the iframe on every prop change, producing a visible "flash" and resetting the inner native PDF viewer's scroll on every edit — slow and disorienting for the editing experience this app is built around. Memoization, debouncing, and double-buffering attempts could reduce frequency but not eliminate the flash, because the iframe swap is intrinsic to the browser's native PDF viewer.

We're amending ADR-0002: keep React-PDF for **export** (it remains the authoritative renderer for downloads), but for the **live preview** add a parallel DOM render pipeline that mirrors the React-PDF tree (`src/preview/` vs `src/pdf/`). The preview is now a regular scrollable `<div>` styled in pt to match React-PDF's coordinate space; edits show up instantly, scroll is preserved by the browser naturally, and there are no iframes.

## Considered options

- **Stay with `<PDFViewer>`** — rejected. Flash and scroll reset are not fixable in user-space; would require replacing the browser's PDF viewer with a custom pdf.js implementation.
- **Custom pdf.js-based preview rendering pages as canvases** — heavier dependency, more code, still slower than DOM. Rejected.
- **Dual render (HTML for preview, React-PDF for export)** — chosen.

## Consequences

- **Drift risk.** Two component trees must stay visually consistent. A change in `src/pdf/` needs a mirroring change in `src/preview/` (or vice versa). The two are intentionally structured in parallel (same filenames, same shapes) so the diff is mechanical. A future visual-regression test (snapshot the preview, snapshot the exported PDF, compare) could enforce this automatically.
- **Two layout engines.** React-PDF uses Yoga (a strict flexbox variant); the browser uses standard CSS. Most styles map directly (using pt units in CSS pins sizes to React-PDF's coordinate space) but pixel-level parity is not guaranteed, particularly for fonts. This is acceptable per ADR-0002's "same visual family" fidelity target.
- **Export still authoritative.** The PDF generated by React-PDF is the artifact users send out. The preview is a fast proxy. If they ever drift visibly, fix the preview to match the PDF, not the other way around.
